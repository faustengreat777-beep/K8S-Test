# ADR-0002: Название продукта, лицензирование open-core и редакции

- Статус: Предложено
- Дата: 2026-10-06
- Язык: [English](0002-product-name-and-open-core-licensing.md) · Русский

## Контекст

Владелец поручил архитектору выбрать интересное название, которого ещё нет на рынке (ответ 2 в Фазе 0), и выбрал модель **open-core**: ядро под Apache-2.0 плюс коммерческий каталог `ee/` (ответ 3a). В спецификации CLI называется `clusterctl` (промпт §56) и `platformctl` (промпт §197). `clusterctl` уже занят: это CLI проекта Kubernetes **Cluster API**, поэтому такое имя привело бы к путанице и конфликтам при установке. Спецификация также требует двух логических редакций: Community/Standard и Enterprise. Enterprise не должна быть «фича-флагом поверх хаотичного кода», а права (entitlements) должны управляться централизованно (промпт §133, §218–219).

## Решение

### Название: **Farvater**

- **Значение.** *Farvater* (русское «фарватер», от нидерландского *vaarwater*) — это безопасный обозначенный судоходный проход, по которому суда идут через сложные воды в порт. Именно это продукт и обещает:
  - он ведёт пользователя от «голой» инфраструктуры к готовому к продакшену кластеру по проверенному безопасному фарватеру;
  - каталог версий и правила совместимости — это «буи», которые отмечают, где идти безопасно;
  - название вписывается в морскую лексику Kubernetes (κυβερνήτης, «рулевой»), Helm и harbor.
- **Работает на обоих языках.** Слово привычно для русского языка и легко произносится по-английски («FAR-vah-ter»). Ни в одном из языков у него нет неудачных значений.
- **Проверка доступности (2026-10-06).** Веб-поиск не выявил программных продуктов, open-source-проектов или компаний в сфере DevOps/Kubernetes/облаков, которые использовали бы это название. Кандидаты, отклонённые потому, что в этой сфере они уже заняты:

| Кандидат | Найденный конфликт |
|---|---|
| Nauarch / Navarch | *Nauarchos* (control plane на Kubernetes для парков агентов), *Navarch* (мультиоблачный провижининг парков GPU), *Navarcos* (менеджер Kubernetes CaaS/PaaS на базе Cluster API) |
| Slipway | GitOps-контроллер для Kubernetes *Slipway*; образы slipwayhq |
| Stapel | Синтаксис сборки образов в **werf** (инструмент CI/CD для Kubernetes) |
| Werf («верфь») | Сам **werf** |
| Keelson | Прямых совпадений нет, но слишком близко к **Keel** (keel.sh, автоматизация обновлений в Kubernetes) |
| Shipwright, Flotilla, Armada, Helmsman, Tiller, Drydock | Существующие проекты CNCF/OSS |
| Lotsman, Kormchiy, Rumb | Свободны, но неудобны для англоговорящих или вызывают слабые ассоциации |

  Официальная проверка товарного знака и регистрация домена — **задачи владельца** до публичного запуска. До тех пор `farvater.io` используется как временное значение для группы API и домена документации.
- **Идентификаторы**:

| Элемент | Значение |
|---|---|
| Продукт | Farvater |
| Серверный бинарник | `farvater-server` (роли: `api`, `worker`, `all`, `migrate`, `admin`) |
| CLI | `farvater` (пользователи могут задать для него алиас) |
| Группа API ClusterSpec | `farvater.io/v1alpha1` |
| Go-модуль | `github.com/faustengreat777-beep/k8s-test` до переименования репозитория (рекомендуемое имя: `farvater`) |
| Префикс API-ключей | `fvt_` |
| Образы контейнеров | `…/farvater-server`, `…/farvater-node-helper` |
| Префикс метрик | `farvater_` |
| Helm-чарт | `farvater` |

### Лицензирование и редакции

- **Редакция Community**: всё, что находится вне `ee/`, под лицензией **Apache-2.0** (`LICENSE` в корне). Это полноценный продукт продакшен-уровня для провижининга и управления жизненным циклом: все провайдеры, дистрибутивы, аддоны, режимы Auto/Simple/Advanced, обновления (upgrade), масштабирование, резервное копирование и восстановление, состояние (health), шаблоны, API, CLI, вебхуки, журнал аудита.
- **Редакция Enterprise**: код в `ee/` под **отдельной коммерческой лицензией** (`ee/LICENSE`). Текст лицензии должен подготовить юрист до того, как в `ee/` появится первый код. До тех пор каталога `ee/` нет. Код Enterprise компилируется только с тегом сборки `ee` и подключается к задокументированным точкам расширения (провайдеры идентификации, авторизатор, модуль вычисления политик, шлюз согласований, приёмники аудита, провайдеры ключей, контроллер парка кластеров).
- **Правило границы open-core**: Enterprise добавляет управление (governance), масштаб и интеграции: политики SSO/SCIM/MFA, пользовательские роли/ABAC, движок политик, согласования, соответствие требованиям (compliance), управление парком кластеров (fleet), KMS/BYOK, пакеты для изолированных (air-gap) установок, эталонную HA-архитектуру, управление затратами, инциденты. Она **никогда не удаляет и не урезает** базовые возможности провижининга и никогда не ограничивает доступ к исправлениям безопасности.
- **Права (entitlements)**: единственный `EntitlementService` проверяет офлайн **файл лицензии с подписью Ed25519** (редакция, функции, лимиты, срок действия). Код вызывает `Has(feature)` и никогда не проверяет `if edition == "enterprise"`. Ключи функций: `enterprise.sso`, `enterprise.scim`, `enterprise.rbac.custom`, `enterprise.policy`, `enterprise.approvals`, `enterprise.audit.export`, `enterprise.compliance`, `enterprise.fleet`, `enterprise.kms`, `enterprise.airgap`, … Фича-флаги для постепенного выката — отдельный механизм, и они никогда не заменяют архитектуру (промпт §219).
- **Вклад в проект**: для ядра под Apache-2.0 — подпись Developer Certificate of Origin (DCO); CLA для вклада в ядро не требуется. В `ee/` изменения вносит только вендор.
- **Сторонние лицензии**: код под GPL/AGPL/SSPL/BSL не линкуется в наши бинарники (лицензионная проверка в CI). AGPL-компоненты (Grafana, Loki, Tempo) только устанавливаются без изменений в кластеры пользователей (ADR-0024).

## Рассмотренные альтернативы

- **Оставить `clusterctl`/`platformctl`**: конфликт имён с Cluster API; кроме того, эти имена слишком общие для бренда.
- **Полностью проприетарная модель**: ограничивает распространение и доверие к инфраструктурному инструменту, который хранит учётные данные с правами root.
- **Ядро под AGPL**: защищает от SaaS-провайдеров, пользующихся проектом бесплатно, но многие компании запрещают AGPL. Apache-2.0 даёт максимальное распространение, а ценность Enterprise сосредоточена в `ee/`.
- **Ядро под BSL/source-available**: негативная реакция сообщества (ср. HashiCorp → форки OpenTofu/OpenBao). Не соответствует выбору владельца.
- **Отдельный приватный репозиторий для ee**: интеллектуальная собственность разделена чище, но изменения, затрагивающие несколько репозиториев, и CI усложняются. Один репозиторий с отдельной лицензией на каталог — устоявшийся подход (GitLab, Grafana, Mattermost).

## Последствия

- Плюсы: самобытное, осмысленное название, которое работает на обоих целевых языках; понятный контракт open-core, укрепляющий доверие сообщества; единое место для логики редакций.
- Минусы: нужно закрепить за собой товарный знак и домен. Коммерческая лицензия требует юридической проработки. Репозиторий следует переименовать до появления кода, иначе путь модуля придётся многократно менять.
