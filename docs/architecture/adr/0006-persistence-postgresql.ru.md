# ADR-0006: PostgreSQL — единственная обязательная зависимость с состоянием; pgx, sqlc и goose

- Статус: Предложено
- Дата: 2026-10-06
- Язык: [English](0006-persistence-postgresql.md) · Русский

## Контекст

Спецификация требует PostgreSQL (промпт §58) и полноценный инструмент миграций с версионированными, обратимыми и автоматизированными миграциями (промпт §88), а также упоминает Redis для очередей (промпт §43, §84). Для self-hosted, изолированных (air-gapped) и HA-установок выгодно иметь как можно меньше компонентов с состоянием. Исследование (2026-10-06): PostgreSQL **18.6** — последний стабильный мажорный релиз, в нём есть встроенная функция `uuidv7()`. PG 19 всё ещё в бете (GA запланирован на конец октября 2026 года). Поддержка PG 14 заканчивается (EOL) в ноябре 2026 года, PG 15 — в ноябре 2027 года. Актуальный инструментарий: pgx v5.11, sqlc v1.31 (генерация кода под pgx/v5), goose v3.28 (MIT, встраиваемый). Бинарник Atlas CLI распространяется под EULA, а в его редакции Community Edition под Apache-2.0 нет части команд.

## Решение

- **Рекомендуется PostgreSQL 18, минимум — 16.** Это единственная обязательная зависимость с состоянием: доменное состояние, очередь заданий (River, ADR-0007), события операций, журнал аудита, зашифрованные секреты, ключи идемпотентности, outbox, сессии. PG 19 войдёт в тестовую матрицу после выхода GA.
- **Драйвер**: `jackc/pgx/v5` (pgxpool) с трассировкой OpenTelemetry (`otelpgx`).
- **Запросы**: SQL пишется вручную и компилируется с помощью **sqlc** в типизированный код на Go. Без ORM. Запросы можно проверить на ревью, а фильтры по тенанту явные.
- **Миграции**: SQL-миграции **goose v3** встроены в бинарник (`embed.FS`) и применяются командой `server migrate` под advisory-блокировкой. Там, где миграция обратима, у неё есть секции Up/Down. Для обновлений (upgrade) без простоя используется схема expand/contract. CI выполняет `up → down → up` и сравнивает дампы схемы (diff).
- **Идентификаторы**: UUIDv7 (`uuidv7()` на PG 18; на 16–17 их генерирует приложение).
- **PostgreSQL внутри кластера для Helm-чарта платформы**: CloudNativePG (Apache-2.0) или внешняя управляемая база данных. **Никаких чартов и образов Bitnami**: в 2025 году бесплатные версионированные образы Bitnami переехали в `bitnamilegacy`, который больше не получает исправлений.

## Рассмотренные альтернативы

| Вариант | Почему нет |
|---|---|
| ORM (GORM, ent) | Из-за скрытых запросов сложнее проверять на ревью фильтры по тенанту и производительность. Кодогенерация ent тяжеловесна. sqlc сохраняет SQL явным и типизированным |
| golang-migrate | Хороший вариант, но встраиваемый Provider API и миграции в виде Go-функций в goose лучше подходят для модели единого бинарника |
| Atlas (декларативный) | Мощное сравнение схем (diff), но CLI по умолчанию распространяется под EULA. Его не стоит распространять в составе продукта под Apache-2.0 |
| MySQL / CockroachDB | Не то, чего требует спецификация. RLS, LISTEN/NOTIFY и драйвер River специфичны для PostgreSQL |
| Redis как второе хранилище | Не нужен (ADR-0007) и добавляет сложности с лицензированием и HA |

## Последствия

- Плюсы: одна база данных, для которой нужно обеспечить эксплуатацию, резервное копирование, защиту и высокую доступность. ACID охватывает состояние, задания, события и аудит одновременно.
- Минусы: при очень большом парке кластеров PostgreSQL становится узким местом по пропускной способности (события и задания). Меры смягчения: секционированные таблицы событий с ограниченным сроком хранения (retention), пул соединений, а позднее — реплики для чтения под дашборды с интенсивным чтением.
