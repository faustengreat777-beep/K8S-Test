# ADR-0022: Балансировка нагрузки и endpoint control plane

- Статус: Предложено
- Дата: 2026-10-06
- Язык: [English](0022-load-balancing-and-control-plane-endpoint.md) · Русский

## Контекст

HA-кластерам нужен стабильный endpoint control plane, а для `Service type=LoadBalancer` нужна реализация (промпт §20: MetalLB, облачный LB, внешний LB, NodePort; для bare metal предложен MetalLB). Исследование (2026-10-06): MetalLB 0.16.1 поддерживается, но всё ещё имеет версию 0.x. FRR-K8s стал его BGP-бэкендом по умолчанию, а классический режим FRR объявлен устаревшим. kube-vip 1.2.x — распространённый способ получить VIP для control plane в kubeadm. Как статическому поду ему нужен `super-admin.conf` на первом узле control plane во время `kubeadm init` (≥ 1.29), а затем `admin.conf`. Cilium LB-IPAM и BGP control plane стабильны, но анонсы L2 в Cilium всё ещё в статусе beta. В Hetzner Cloud (сети третьего уровня) VIP на основе ARP (MetalLB L2, kube-vip ARP, keepalived) не работают. Там нужно использовать Hetzner Load Balancer через hcloud-cloud-controller-manager либо Primary/Floating IP, переназначаемые через API.

## Решение

- **Endpoint control plane** (выбирает движок принятия решений на основе возможностей провайдера и заявленной сети):
  - bare metal / VPS со смежностью на уровне L2 → статический под **kube-vip** (ARP), который записывается до `kubeadm init --control-plane-endpoint`; на первом узле применяется переключение super-admin.conf → admin.conf;
  - сети с поддержкой BGP → kube-vip в режиме BGP;
  - **внешний балансировщик нагрузки**, указанный пользователем (существующий HAProxy/F5 и т. п.) → используется его адрес;
  - облачные провайдеры → балансировщик нагрузки провайдера (Hetzner LB, AWS NLB, …);
  - единственный узел control plane → адрес узла (без HA, с WARNING в production).
- **Балансировщик нагрузки для сервисов**:
  - bare metal с L2 → **MetalLB** (по умолчанию режим L2; BGP через FRR-K8s, если заданы пиры);
  - кластеры на Cilium с BGP-пирами → **Cilium LB-IPAM + BGP control plane** как предпочтительная альтернатива. Анонсы L2 в Cilium предлагаются только с пометкой «beta», и режим Auto не выбирает их для production;
  - облака → балансировщики нагрузки через CCM провайдера (например, hcloud-cloud-controller-manager ≥ 1.38; версии ≤ 1.30.0 заблокированы в каталоге);
  - разработка без LB → NodePort.
- Движок совместимости **блокирует** MetalLB L2 и kube-vip ARP у провайдеров с пометкой «только L3» (Hetzner Cloud) и в качестве исправления (remediation) указывает на LB провайдера.

## Рассмотренные альтернативы

- **keepalived + HAProxy на узлах control plane**: проверенное решение, но больше движущихся частей, которые нужно настраивать и обновлять. Возможно позже как вариант «внешний LB на узлах».
- **Анонсы L2 в Cilium по умолчанию**: меньше компонентов в кластерах на Cilium, но статус beta и дополнительная нагрузка на API-сервер (одна аренда (lease) на сервис).
- **MetalLB везде**: не работает в облаках с L3-сетями.

## Последствия

- Плюсы: корректные значения по умолчанию для каждой среды, а известные ловушки заблокированы правилами.
- Минусы: нужно поддерживать несколько реализаций LB. Каждой требуется покрытие E2E-тестами (для тестов L2 нужен Tier-3 или специальная настройка сети).
