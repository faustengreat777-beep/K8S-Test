# ADR-0023: Хранилище по умолчанию

- Статус: Предложено
- Дата: 2026-10-06
- Язык: [English](0023-storage-defaults.md) · Русский

## Контекст

Спецификация требует абстракции хранилища с поддержкой local-path, NFS, Longhorn, Ceph и облачных CSI, а также подходящего варианта по умолчанию для пресета Production (промпт §21). Исследование (2026-10-06):
- **local-path-provisioner** v0.0.37 не публикует Helm-репозиторий.
- **csi-driver-nfs** — актуальная версия v4.13.x.
- **Longhorn 1.13.0** (2026-09-29) требует **Kubernetes ≥ 1.34**; его движок данных V2 (SPDK) достиг GA и предъявляет требования к hugepages и ядру.
- **Rook-Ceph 1.20.8** поддерживает Kubernetes 1.31–1.37.
- **OpenEBS 4.6** включает LocalPV и Mayastor.
- **Community-редакция MinIO архивирована и не поддерживается**, поэтому она не подходит в качестве встроенного S3.

## Решение

| Контекст | По умолчанию | Альтернативы |
|---|---|---|
| Development, Minimal, Edge | **local-path** (его чарт размещаем мы), StorageClass по умолчанию | — |
| Production на bare metal с ≥ 3 рабочими узлами | **Longhorn** (движок данных V1, 3 реплики, StorageClass по умолчанию, цель резервного копирования = хранилище резервных копий кластера) | Rook-Ceph для больших объёмов / высокого IO или если у пользователя есть опыт работы с Ceph; NFS CSI для существующих NAS |
| Production на bare metal с < 3 рабочими узлами | Longhorn с числом реплик, равным числу рабочих узлов, плюс WARNING (сниженная избыточность) либо local-path плюс WARNING (без репликации) | NFS |
| AI/ML, High Storage IO | Rook-Ceph (блочное хранилище + объектное хранилище RGW) | Движок V2 в Longhorn (только по явному выбору, с проверками ядра/hugepages) |
| Облака | CSI провайдера (например, hcloud CSI для томов RWO) | Longhorn на облачных дисках |
| В кластере нужно объектное хранилище (Loki, Tempo, Velero) | Внешний S3-совместимый endpoint (рекомендуется) или **Rook-Ceph RGW** | SeaweedFS (Apache-2.0); **MinIO не входит в поставку** (архивирован) |

- Движок совместимости проверяет выполнение требований аддонов: для Longhorn с 3 репликами — ≥ 3 узлов, доступных для планирования; Longhorn 1.13 → K8s ≥ 1.34; пакеты клиентов iSCSI/NFS, установленные слоем bootstrap; минимальный объём дискового пространства; ровно один StorageClass по умолчанию.
- Проверки состояния (health) включают необязательный smoke-тест PVC во время `health.verify`.

## Рассмотренные альтернативы

- **OpenEBS по умолчанию**: достойная альтернатива (Apache-2.0); остаётся кандидатом в каталоге. У Longhorn проще UX и есть встроенная интеграция с резервным копированием.
- **Ceph по умолчанию**: мощное решение, но слишком тяжёлое для небольших кластеров (затраты ресурсов и стоимость эксплуатации).
- **MinIO для S3 внутри кластера**: upstream архивирован, есть неисправленная CVE, на которую указала Grafana. Неприемлемо.

## Последствия

- Плюсы: разумные значения по умолчанию для каждого размера и среды; рискованные варианты «без репликации в production» выбираются явно.
- Минусы: нужно тестировать несколько аддонов хранилища (для содержательных тестов Longhorn/Ceph нужны реальные диски Tier-3).
