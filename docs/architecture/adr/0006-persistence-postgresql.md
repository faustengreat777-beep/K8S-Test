# ADR-0006: PostgreSQL as the only required stateful dependency; pgx, sqlc and goose

- Status: Proposed
- Date: 2026-10-06
- Language: English · [Русский](0006-persistence-postgresql.ru.md)

## Context

The spec mandates PostgreSQL (prompt §58), a proper migration tool with versioned, reversible and automated migrations (prompt §88), and lists Redis for queues (prompt §43, §84). Self-hosted, air-gapped and HA installs benefit from as few stateful components as possible. Research (2026-10-06): PostgreSQL **18** is the latest stable major release (current minor 18.6), with built-in `uuidv7()`. PG 19 is still in beta (GA targeted late October 2026). PG 14 reaches EOL in Nov 2026 and PG 15 in Nov 2027. Current tooling: pgx v5.11, sqlc v1.31 (pgx/v5 output), goose v3.28 (MIT, embeddable). The Atlas CLI binary ships under a EULA, and its Apache-2.0 Community Edition lacks some commands.

## Decision

- **PostgreSQL 18 recommended, 16 minimum.** It is the single required stateful dependency: domain state, job queue (River, ADR-0007), operation events, audit log, encrypted secrets, idempotency keys, outbox, sessions. PG 19 joins the test matrix after GA.
- **Driver**: `jackc/pgx/v5` (pgxpool) with OpenTelemetry tracing (`otelpgx`).
- **Queries**: hand-written SQL compiled with **sqlc** into typed Go. No ORM. Queries are reviewable and tenancy filters are explicit.
- **Migrations**: **goose v3** SQL migrations embedded in the binary (`embed.FS`), applied by `server migrate` under an advisory lock. They carry Up/Down sections where reversible. Expand/contract is used for zero-downtime upgrades. CI runs `up → down → up` and a schema-dump diff check.
- **IDs**: UUIDv7 (`uuidv7()` on PG 18; generated by the app on 16–17).
- **In-cluster PostgreSQL for the platform's Helm chart**: CloudNativePG (Apache-2.0) or an external managed database. **No Bitnami charts or images**, since Bitnami's free versioned images moved to the unpatched `bitnamilegacy` in 2025.

## Alternatives considered

| Option | Why not |
|---|---|
| ORM (GORM, ent) | Hidden queries make tenancy filters and performance harder to review. ent's codegen is heavy. sqlc keeps SQL explicit and typed |
| golang-migrate | Fine, but goose's embedded Provider API and Go-function migrations fit the single-binary model better |
| Atlas (declarative) | Strong diffing, but the default CLI is under a EULA. Avoid redistributing it in an Apache-2.0 product |
| MySQL / CockroachDB | Not what the spec asks for. RLS, LISTEN/NOTIFY and the River driver are PostgreSQL-specific |
| Redis as a second store | Not needed (ADR-0007), and adds licensing and HA complexity |

## Consequences

- Positive: one database to operate, back up, secure and make highly available. ACID across state, jobs, events and audit.
- Negative: PostgreSQL becomes the throughput bottleneck at very large fleet scale (events and jobs). Mitigations: partitioned event tables with retention, connection pooling, and later read replicas for read-heavy dashboards.
